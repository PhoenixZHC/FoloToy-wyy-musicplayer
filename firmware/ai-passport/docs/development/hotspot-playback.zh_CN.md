# 手机热点播放稳定性

开发变更：2026-11-03，Asia/Shanghai；来源设备：Ubuntu 开发电脑。基于 Folo Music 2.1，尚未发布，不代表设备验收通过。

## 按审阅顺序修复

1. 播放器初始化自己的驱动后设置 WIFI_PS_NONE，并检查返回值；配网页面也检查返回值。退出配网会反初始化 Wi-Fi，不能依靠配网阶段设置覆盖播放阶段。关闭 modem sleep 降低接收延迟，但增加功耗。
2. audio_download.c 使用优先级 5、6144 字节栈的独立任务处理 HTTP/TLS；优先级 6 的解码任务从有上限的 16 KiB FreeRTOS 流缓冲非阻塞取数据，保留原有 8 KiB MP3 输入。首次及断粮后等待 8 KiB 储备，或等待下载结束；新增 AUDIO_STREAM_BUFFERING，播放中也能显示缓冲状态。首次 TLS 完成后再分配声卡/DMA；停止时先取消并等待下载任务，再释放队列，不强删活跃网络任务。
3. worker 空闲时每 250 ms 检查 Wi-Fi；断线回调记录原因、发布重连请求，不等待、不操作 LVGL。最多尝试六次，退避上限 8 秒；取得新 IP 后重置预算，手动重试开启新预算。HTTP 恢复在连续未成功推进 8 KiB 时最多重试六次，无进展最多等待 30 秒，退避从 250 ms 增至 4 秒。连接/响应头超时为 3 秒，读取超时为 1 秒；阻塞 SDK 调用可能使截止时间延后。超时连接连续三秒无数据后重建，预算耗尽明确报错。
4. 正常结束必须满足 HTTP 报文完整；已知总长度时还要满足字节数。暂时 EAGAIN 不算结束。中断后从实际成功入队的字节数续传，保留解码器及 MP3 位储备。续传必须返回 206，并校验 Content-Range、响应长度和总长度；存在强 ETag 或 Last-Modified 时使用 If-Range，资源变化或服务端忽略 Range 均明确失败。请求使用 identity 编码，保留证书验证，禁止 HTTPS 降级重定向；未知长度的 chunked 响应必须由传输层确认完整结束。

存在音频任务时暂停推测性元数据预取，包括暂停/缓冲状态；主动浏览仍可用。Wi-Fi RX/TX 数量、音频码率和 Flash 分区不变。

## 内存与诊断

队列和下载栈新增约 22 KiB，另有上下文及 RTOS 管理开销。设备没有 PSRAM，不采用静默缩小缓冲的降级，分配失败明确报错。按请求的 128 kbps 估算，8 KiB 约为 0.51 秒压缩音频，不能补偿长期不足的蜂窝网速。

日志区分解码取队列与网络读取：Playback Wi-Fi 的 RSSI/信道/状态，断线原因与重连次数，network 已接收/排队字节和最长读取时间，Rebuffer audio 断粮次数，以及空闲/最大连续堆。不输出 URL、密码、Cookie 或原始响应头。需要关联无线指标与读取耗时；Wi-Fi RSSI 良好不代表蜂窝网或 CDN 稳定。

### 播放故障与补充修复

第一次实机配网、扫码登录、20 个歌单加载成功，音频返回 HTTP 200 并识别 44.1 kHz/双声道/128 kbps MP3。但音频初始化后空闲堆仅 4,340 字节、最大连续块 2,688 字节；收到 9,912 字节后进入重缓冲，六次连接恢复均 select 超时，最终明确报 ESP_ERR_HTTP_CONNECT，未错误跳到下一首。RSSI 在 -46 至 -60 dBm。此轮播放验收失败；没有内存分配失败日志，不能仅凭低堆把连接超时全部归因于内存。

代码确认最后一次歌词 WEAPI 请求仍保留闲置 TLS 客户端及固定 RX。补充 netease_direct_client_release_connection：启动音频前、音频活动期间主动浏览请求完成后，由同一 worker 释放闲置连接；保留登录、请求配置及元数据缓存。新增回归确认只清理一次、重复调用安全、账号和 NVS 不变、随后请求重新连接。三个客户端主机程序、ESP-IDF 构建、合并分段和完整镜像回读/哈希校验通过。

### 实机清单

按[部署指南](../../../../docs/deployment.md)烧录。仅在设备已有匹配的 7 MiB factory 分区时，才可在 0x10000 只写 app 保留设置；0x0 完整 8 MiB 镜像会清空 Wi-Fi、账号和显示设置。先核对设备和分区布局。

1. 相同歌曲分别使用路由器与手机 2.4 GHz 热点，比较亮屏/熄屏；记录手机型号、蜂窝网条件、距离，不记录凭据。
2. 播放中短暂关闭热点再恢复；确认显示缓冲、自动重连后进度继续，不重复播放开头，不把断流当作播完跳歌。
3. 热点关闭超过预算；确认明确错误及手动重试有效；正常播放结束仍只切换一次。
4. 暂停/继续、连续切歌、播放中浏览，以及缓冲时退出；加入主动列表请求中同时掉线场景，业务 worker 必须等同步 API 返回才能维护 Wi-Fi。检查崩溃、任务泄漏、空闲/最大堆持续下降或按键失效。
5. 户外连续播放，对比断粮次数、读取延迟、RSSI 和耗电。听感、无线表现及峰值 RAM 待真机验证。
