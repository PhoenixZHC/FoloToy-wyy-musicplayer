# QQ 音乐直连与双平台账号开发方案

更新时间：2026-11-10T17:07:00+08:00（Asia/Shanghai）；来源设备：Ubuntu 开发电脑。

状态：2026-11-11 已完成双平台集成，QQ 播放、封面、同步歌词和网络检测正常使用路径经用户实机确认，纳入正式 2.3.0。历史预检及实现过程按原日期保留；长期播放、弱网、异常分支和网易云完整回归仍未完成。见[2.3.0 说明](releases/v2.3.0.zh_CN.md)和[实施记录](network-qq-media-validation.md)。

## 目标与范围

2026-11-10 用户确认并授权本会话实施：QQ 音乐封面与同步歌词、设置内网络连通测试均已接入开发代码，主机与构建验证通过；新代码未烧录，实机验收仍待完成。具体范围见[后续开发计划](development-plan.md)，证据见[实施验证记录](network-qq-media-validation.md)；不由本文历史预检结果替代。

- 在现有 Folo Music 中增加 QQ 音乐，与网易云音乐并列。
- 必须设备直连：账号授权、音乐接口和音频均由设备直接访问对应平台及其 CDN，不增加电脑、NAS、自建或第三方中转服务，不要求用户手工导入 Cookie。
- 联网成功后进入平台选择页，选择 QQ 音乐或网易云音乐，再进入对应登录或歌单流程。QQ 音乐优先采用 QQ 音乐 App 扫码，网易云使用网易云音乐 App 扫码。
- 设置一级菜单新增「退出登录」，作用范围为当前平台账号。
- 首版沿用 MP3 播放、歌单与歌曲浏览、上一首/下一首、封面和歌词等现有能力，不扩展汽水音乐、无损解码或其他无关功能。平台实际不提供的资源需明确反馈。

## 当前代码基础

- 硬件为 ESP32-C3 / 8 MiB Flash / 无 PSRAM，当前正式路线为网易云 EAPI/WEAPI 设备直连。
- `firmware/ai-passport/main/main.c` 在配网完成或已有网络配置时直接进入网易云应用，目前没有平台选择页。
- Wi-Fi 页面退出会释放网络资源，网易云应用有自己的联网生命周期。新增选择页不能把「保存过 Wi-Fi 配置」当成「已经联网」；需要梳理配网交接、自动重连与平台应用间的网络归属，避免重复初始化或退出旧页面后断网。
- 当前二维码页面通过 `lv_qrcode_update` 对网易云的二维码文本进行编码；QQ 开源实现返回 PNG 图片，需要增加有界图片解析和显示支持，不能将图片字节作为二维码文本再次编码。
- 当前音频模块使用 Helix MP3 解码。歌曲、歌单和账号模型以网易云为主，歌曲标识使用整数，不能直接承载 QQ 的字符串 MID。
- 网易云已有「设置 → 账号 → 退出当前账号」及确认页，直连适配器通过 `netease_direct_session_clear` 清除本机登录态。新增的是双平台统一的设置一级入口及相应清理、跳转行为，不把已有网易云退出逻辑描述为完全缺失。

## 调研依据与验证边界

主要参考 [L-1124/QQMusicApi](https://github.com/L-1124/QQMusicApi)，协议按设备端需要用 C 实现，不在设备或服务端运行 Python 库。

| 环节 | 已核查内容 | 当前证据范围 |
| --- | --- | --- |
| 登录方式 | [登录教程](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/login.md)区分手机 QQ、微信和 QQ 音乐 App 扫码 | 文档与源码核查；不同扫码客户端不能混为一谈 |
| QQ 音乐 App 扫码 | [login.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/login.py)包含 `CreateQRCode`、MQTT 状态通知及登录凭证交换 | 本机与 C3 独立实现扫码及凭据交换通过 |
| 扫码状态连接 | [mqtt.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/utils/mqtt.py)使用 MQTT 5.0 over WSS，初始入口为 `mu.y.qq.com:443/ws/handshake` | 设备直接连接腾讯，仍需验证鉴权属性、订阅、分帧、重定向与超时处理 |
| 手机 QQ 授权码 | 本轮直接请求腾讯 `ptqrshow`，获得 HTTP 200、有效 PNG 及扫码会话 Cookie | 仅验证手机 QQ 的二维码获取入口；未扫码，不代表 QQ 音乐 App 登录或播放通过；未保存二维码、Cookie 或其他凭据 |
| 会话管理 | 登录模块含凭证检查和刷新；模型区分账号、密钥、刷新信息及登录类型 | 本机及 C3 检查、刷新、NVS 保存和重启恢复通过；失败路径主要由主机替身覆盖 |
| 歌单 | 用户模块与歌单模块提供自建歌单、收藏歌单和歌单歌曲读取 | 本机自建、收藏接口及 8 首分页通过；本账号收藏列表为空，非空收藏及设备分页待验收 |
| 音频地址 | [song.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/song.py)有 `get_song_urls`、`MP3_128` 和 `MP3_320` | C3 整曲 MP3 解码自然结束及暂停/继续通过；更多账号、会员/试听边界仍待覆盖 |

库中需要的请求签名有本地算法实现，可参考 [sign.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/algorithms/sign.py)。仅移植实际使用的请求及其前置条件；QQ 音乐 App 二维码创建还涉及客户端平台参数，不能假定只有获取二维码和订阅消息两步。

ESP MQTT 已有 MQTT 5/WSS 基础能力，但已核查的公开连接属性接口未见 QQ 参考实现使用的 `Authentication Method` 对应配置项，不能直接宣称现成 SDK 已完全兼容。实施时先验证项目实际组件版本、CONNECT/订阅属性及服务端响应，再决定最小的协议适配方式。

QQMusicApi 标明 GPL-3.0-or-later；移植前核对本项目及所用代码的许可兼容性，保留必要的来源与许可说明。仓库更新和离线测试不能替代真实账号与设备验证。

## 页面与按键流程

```text
启动 / 完成 Wi-Fi 配置
        ↓
实际联网成功
        ↓
选择音乐平台：网易云音乐 / QQ 音乐
        ↓
检查所选平台保存的登录态
        ├─ 有效 → 进入该平台歌单
        ├─ 网络错误 → 明确提示并允许重试，不清除账号
        └─ 未登录或明确失效 → 显示该平台二维码
                                      ↓
                             等待扫码 → 等待手机确认
                                      ↓
                             获取并保存凭证 → 进入歌单
```

- 每次启动联网后显示平台选择页；可记住上次平台作为默认选中项，不自动跳过选择。
- 平台选择页：↑↓选择，OK 进入；显示对应平台的登录状态，不能仅凭本地存在凭证就标成已验证有效。
- 二维码页明确标注平台和所需扫码 App；短按 OK 刷新，长按 OK 返回平台选择。刷新、返回或切换平台后，旧扫码会话的结果不得写入新会话或更新已退出页面。
- QQ 二维码保持黑白对比与留白，不随日夜主题反色；图片尺寸、解压大小和缩放均有限制，避免模糊缩放影响扫描。
- 扫码过期、用户拒绝、需要额外验证、网络错误分别提示；不把它们都显示成登录过期。若 QQ 音乐 App 路线不可用，报告原因，不静默换成手机 QQ 扫码或中转服务。
- 进入播放器后，设置提供「切换音乐平台」以返回选择页；切换保留双方已保存账号，不等同于退出登录。
- 沿用现有首键唤醒规则、时间状态栏与日夜配色；网络操作在 worker 中执行，不阻塞按键回调。

## 设置中的退出登录

入口为「设置 → 退出登录」，直接可见，不再要求先进入「账号」子菜单；账号信息可继续保留在账号页，但退出操作使用同一条处理链路。

1. 进入确认页，展示当前平台及昵称，默认选中「取消」。说明只清除本设备当前平台登录，保留网络和另一平台账号。
2. 取消时保留播放、登录和页面上下文。
3. 确认后停止当前播放，取消当前平台任务与扫码流程，使旧回调失效；在 worker 中清除该平台的本地凭证及刷新凭证。
4. 清理当前平台的歌单、歌曲、播放 URL、封面、歌词和播放队列等账号相关缓存；另一平台凭证、Wi-Fi、音量、亮度、日夜及熄屏偏好保留。
5. 持久化清除成功后返回平台选择页，当前平台显示未登录。再次选中该平台时获取新二维码；重启不得恢复刚退出的旧账号。
6. 清除失败必须明确提示，不能显示「已退出」。等待重试期间不得继续使用待退出的凭证发起请求或恢复播放；只有清除成功后才报告退出完成。
7. 这里的退出指本设备的本地退出，不宣称已撤销平台全部授权、让手机退出或让其他设备下线；若后续调用平台退出接口，需单独核对接口作用范围。

「切换音乐平台」与「退出登录」必须区分：前者保留账号，后者清除当前平台账号。没有当前已登录账号时，退出项应不可用或明确提示未登录，不能清除另一平台的会话。

## 最小实现边界与资源管理

- 增加平台选择页、QQ 直连协议组件及薄适配层；为现有播放器提供按平台分发的登录、歌单、歌曲、媒体与退出接口，不复制两套完整 UI 或重构无关模块。
- 公共歌曲标识支持平台类型及不透明字符串；QQ 的 `mid`、`media_mid`、歌曲类型等取流字段按实际接口保留，不截断或强转整数。网易云使用其真实 ID，不制造业务编号。
- 两个平台会话分别存储；账号缓存键至少包含平台、账号和资源标识。升级保留已有网易云登录及 Wi-Fi，不要求清空 NVS。
- 同一时刻只激活一个平台客户端。切换时停止播放、取消旧任务、释放连接与媒体缓存，完成清理后再启动新平台；共享 Wi-Fi 不随平台页面误退出。
- QQ 登录成功取得凭证后释放 MQTT/WSS 和二维码临时内存，再进入歌单和播放；凭证交换若需与 WSS 短暂并存，必须实测该阶段的峰值，而不能只测播放时空闲堆。
- 保留现有音频缓冲、下载/解码分离及播放前释放闲置 API TLS 的措施。只按需加载当前分页，不同时常驻两平台歌单和完整响应。
- 歌曲仅有试听、无 MP3 或权限不足时明确提示，不把试听当整曲、不转用其他平台的同名歌、不引入在线转码服务。
- 如与[顺序/随机播放方案](playback-mode-plan.md)一同实施，播放队列绑定平台、账号和歌单；退出、账号切换或平台切换时清理旧队列，不复用旧资源。

## 实施顺序与验收

实施顺序：QQ 音乐 App 创建二维码与 WSS 登录验证 → 凭证保存/恢复 → 个人歌单及 MP3 整曲取流 → 设备播放与内存验证 → 平台选择页及统一设置 → 网易云回归。

必须覆盖：

- 新配网及已保存 Wi-Fi 自动连接，只有实际联网成功后才进入平台选择；断网、连接失败可重试或重新选网。
- 两个平台二维码显示与手机扫描，等待扫码/确认、过期、拒绝、刷新、返回及过期回调隔离；QQ 路线全程无需中转或手工 Cookie。
- QQ 登录、凭证持久化、重启恢复、失效后重新扫码；临时网络失败不误删账号，持久化失败不报保存成功。
- 双方歌单及分页、字符串 MID、播放/暂停、跨页切歌、自动切歌、封面和歌词；普通及有相应权限的会员账号、整曲/试听/不可播放分别验证。
- 播放中切换平台，反复切换、返回、重新扫码，无串号、串歌、旧页面更新或累计资源泄漏。
- 设置一级退出入口、默认取消、确认退出、清除失败、重启不恢复已退出账号；退出任一平台不影响另一平台账号和网络/显示偏好。
- C3 上记录登录连接、凭证交换、播放和切换的空闲堆与最大连续块；用实测确定缓冲及消息上限，不凭 Flash 余量承诺运行内存足够。
- 运行相关主机协议/状态机测试、项目要求的静态检查与固件构建，分别报告设备实测和未验证项；二维码接口可达不能代替完整登录和整曲播放验收。

实施边界：按照用户决定保留当前许可，协议组件独立实现，不移植 GPL 参考代码。2026-11-10 匿名真实请求证明 CreateQRCode 使用精简 comm/param 可以成功，返回 data:image/png;base64 前缀的 150×150、1-bit 调色板 PNG，expiresIn 为 900 秒；这是一轮接口观测，不保证服务端以后不要求其他参数。独立 C MQTT 编解码器被本机验证工具复用，认证及订阅成功，手机确认后收到 scanned/cookies 并成功换取最终凭证；主机凭据仅在内存中使用、未落盘，会话已结束。首次交换复用二维码创建参数时返回 1000，改用 App ct=11/cv=20090008/v=20090008 后成功，C 组件已同步。真实账号凭据检查、刷新及刷新后检查通过；8 首中 7 首返回 104003，1 首获整曲 MP3 授权，未绕过权限。

有界 PNG 解析验证 CRC、尺寸、黑白调色板、解压输出长度和五种行过滤，不把 PNG 再编码为二维码文本。已从独立实机预检接入正式开发入口，订阅确认后才显示 QQ 二维码。App 的 UrlGetVkey 不保证带 CDN 基址，实际调用 GetCdnDispatch 获取；本机观察到 aqqmusic.tc.qq.com 节点。新增 JSON 切片投影避免完整 cJSON 对象树，8 首真实响应约 18 KiB，设备响应上限为 32 KiB；MID、媒体 MID、歌曲类型和整曲文件长度保留，超限或资源不匹配明确失败，不截断标识。

预检通过 -DQQMUSIC_DEVICE_PREFLIGHT=ON 单独构建，普通构建不启用预检配网入口。其 NVS 写独立 qqmusic 会话，按用户授权可通过串口保存独立 qq_test_wifi 测试网络，读取但不清理原 Wi-Fi；用于扫码、凭据保存/恢复/刷新、有限分页寻找有权限 MP3、解码播放和分阶段堆/栈记录。详见固件[构建与验证说明](../firmware/ai-passport/docs/development/build-and-test.zh_CN.md)。主机静态门禁覆盖 21 个 C 测试程序、9 个 Python 登录回归和 4 个打包回归；会话及 provider 替身覆盖保存/退出失败、网络失败、认证失效、刷新串号拒绝及跨平台隔离。正式版实机验收仍在进行，不预先承诺全部账号、曲目或网络场景均可用。
