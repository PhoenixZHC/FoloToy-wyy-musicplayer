# 网易云官方接口独立固件设计

## 目标

在项目根目录新增 `netease-official-firmware/`，制作一套由 ESP32-C3 直接访问网易云官方开放平台的独立固件。它只服务于用户自己的一台开发验证设备，不依赖本项目 `server/` 或其他中转服务。

现有 `firmware/`、`server/`、数据库、启动脚本和已烧录固件保持不变。新旧两套固件分别构建、分别烧录，用户可以随时把旧固件重新烧回设备。

## 范围

首版只实现以下能力：

1. 连接 2.4 GHz Wi-Fi。
2. 使用网易云官方二维码完成用户登录。
3. 保存并自动刷新用户令牌。
4. 显示用户创建和收藏的歌单。
5. 显示歌单内歌曲。
6. 获取官方播放地址并播放。
7. 保留现有界面、按键、音量和 MP3 播放能力。

首版不实现搜索、推荐、收藏操作、播放记录上报、账号管理后台、远程升级、中转服务或多设备密钥管理。

## 方案选择

采用“完全独立目录 + 固件直连官方接口”。相比修改现有固件或保留中转服务，这个方案最符合“不影响当前可用版本”和“单设备开发验证”的要求。

新固件复用现有 ESP32-C3 硬件层、LVGL 页面、Wi-Fi 配网和音频播放代码，但所有文件都复制到新目录后再修改。旧目录中的源码不被新固件引用，也不作为新固件构建输入。

## 组件职责

### `netease_official_client`

负责官方请求的公共参数、参数排序、URL 编码、RSA-SHA256 签名、HTTPS 请求和 JSON 解析。它向应用层提供登录、令牌刷新、歌单、歌曲详情和播放地址等稳定接口，不把官方原始 JSON 直接交给界面。

所有请求使用官方域名 `https://openapi.music.163.com`。公共参数包括 `appId`、`signType=RSA_SHA256`、`timestamp`、`bizContent`、`device`、可选 `accessToken` 和计算得到的 `sign`。签名时排除空值与 `sign`，其余参数按 ASCII 升序拼接，再使用应用私钥执行 SHA256WithRSA 并进行 Base64 编码。

开发验证阶段暂用已确认的第二组设备参数：

- `channel=iotapitest`
- `deviceType=openapi`
- `os=openapi`
- `brand=iotapitest`

`deviceId` 使用设备 MAC 派生出的稳定标识，避免每次启动变化。接口正式落地时，以用户已登录的官方文档中对应接口参数表为唯一依据，不根据第三方项目猜测路径或字段。

### 令牌存储

用户授权成功后，将 `accessToken`、`refreshToken` 和过期时间保存到独立 NVS 命名空间。启动时优先读取已有令牌；令牌接近过期时自动刷新。接口明确返回登录失效时，只自动刷新并重试一次，避免无限循环。

刷新失败时清除失效令牌并返回二维码登录页。切换账号也只清除新固件自己的令牌，不擦除 Wi-Fi 或旧固件的数据分区定义。

### 应用和界面

应用层继续使用后台任务执行联网、签名、JSON 解析和音频启动，按键回调不执行耗时操作。LVGL 仍只在受保护的界面上下文中更新，并继续复用屏幕对象，适应 ESP32-C3 无 PSRAM 的内存限制。

旧版 Cloud URL、注册码、设备注册和中转服务页面从新固件流程中移除。新固件首次启动只需要配置 Wi-Fi，然后进入网易云登录流程。

### 音频播放

歌单歌曲接口先取得歌曲编号。为控制内存和每日 5000 次接口额度，只为当前可见行按需查询歌曲名称和歌手。用户选中歌曲时再获取新的播放地址，播放地址不写入 NVS，也不跨重启复用。

播放继续使用现有 `audio_stream` 组件，通过 HTTPS 拉取音频、Helix 解码并输出到 ES8311。首版保持现有 128 kbps 默认请求和现有音量操作。

## 数据流程

1. 固件启动并连接 Wi-Fi。
2. 通过网络校时，确认系统时间可用于官方签名。
3. 读取 NVS 令牌；有效则直接加载歌单。
4. 无有效令牌时，获取匿名登录凭据和二维码信息并显示二维码。
5. 定时轮询扫码状态；成功后保存用户令牌。
6. 分别获取用户创建和收藏的歌单，按歌单编号去重后显示。
7. 进入歌单后分页获取歌曲编号，并按当前可见区域加载歌曲信息。
8. 用户选择歌曲时获取即时播放地址并启动播放。
9. 令牌过期时刷新一次并重放原请求；刷新失败则回到登录页。

## 错误处理

- 网络不可用：保留当前页面，显示网络错误并允许重试。
- 网络时间未校准：不发送签名请求，明确提示校时失败。
- 二维码过期：停止旧轮询，提示重新生成。
- 签名或参数错误：显示官方错误码，日志记录接口名称和错误码。
- 令牌失效：刷新一次；失败后清除令牌并重新登录。
- 歌曲无版权、需要会员或无播放地址：返回歌曲列表并显示官方原因，不进入假播放状态。
- 响应超过内存上限或 JSON 不完整：立即返回可识别错误，不截断后继续解析。
- 日志禁止输出 AppSecret、私钥、完整令牌、签名原文或完整授权响应。

## 密钥与开发安全

真实 AppID、轮换后的 AppSecret 和私钥由用户写入本机 `netease_secrets.h`，不得通过聊天发送，也不得进入版本记录。之前在截图中暴露过的 AppSecret 应先在官方平台轮换，再用于真机联调。

开发版不启用 Secure Boot、Flash Encryption 或不可逆 eFuse 设置，因此设备仍可正常擦除和烧写其他固件。必须明确接受：即使源码文件被忽略，编译后的私钥和 AppSecret 仍存在于固件镜像中，具备条件的人可以提取；本设计只适用于用户自己的单台开发验证设备。

## 测试

### 本地主机测试

- 公共参数过滤和 ASCII 排序。
- `bizContent`、`device` 的编码。
- 固定测试私钥下的 RSA-SHA256 签名结果。
- 二维码各状态解析。
- 令牌有效、临近过期、刷新失败的状态转换。
- 创建歌单与收藏歌单合并去重。
- 歌曲列表、歌曲详情、播放地址和官方错误响应解析。
- 超长和缺字段响应必须返回失败。

测试只使用专用测试密钥和脱敏样例，不使用真实账号数据。

### 固件构建

在已激活的 ESP-IDF 5.5.4 环境中执行完整构建，并验证目标为 ESP32-C3、8 MB Flash、无 PSRAM。构建产物必须只来自 `netease-official-firmware/`，不得链接旧目录组件。

### 真机联调

按顺序验证 Wi-Fi、校时、二维码显示、扫码授权、歌单读取、歌曲列表、歌曲播放、暂停恢复、音量调节、重启免登录、令牌刷新失败后重新登录。只有真机测试才能确认官方账号权限、音频外链 TLS 兼容性和实际播放稳定性。

## 完成标准

- 新目录可独立完成 ESP-IDF 构建。
- 不启动 `server/` 也能完成登录、获取歌单和播放。
- 旧 `firmware/` 与 `server/` 的代码没有改动。
- 项目文件中不存在真实 AppSecret、私钥或用户令牌。
- 所有接口错误均明确暴露，不静默兜底或伪造成功。
- 本地主机测试与固件构建全部通过。
- 真机完成一次扫码登录、一次歌单读取和一次歌曲播放。
- 未启用 Secure Boot、Flash Encryption 或不可逆 eFuse 设置。
