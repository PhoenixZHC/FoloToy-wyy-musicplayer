# 网易云设备直连实施计划

## 目标

在 FoloToy ESP32-C3（8 MB Flash、无 PSRAM）上实现网易云客户端协议直连。用户完成 Wi-Fi 配置后，设备显示网易云扫码登录二维码；用户扫码后设备保存登录态，直接获取歌单和歌曲信息、取得播放地址并连接音频 CDN 播放。正常使用时不依赖本仓库 `server/`、`ncm-cli`、电脑、手机应用代理或其他自建服务。

本路线研究并移植开源网易云客户端协议实现，不依赖网易云官方开放平台的厂商设备参数。网络请求、登录态与音频连接全部由设备完成。

用户明确排除官方开放平台路线，后续只继续开源客户端协议直连。

## 当前项目基线

- 正式基线固件：`firmware/ai-passport/` 和 `firmware/components/`；现有中转版继续保留，完成新版本真机验收之前不得替换默认发布路径。
- 现有设备客户端 `firmware/components/netease_client/` 依赖设备注册、中转服务、HMAC 签名与 JSON API。
- 现有 `firmware/components/audio_stream/` 已实现 HTTPS MP3 流式拉取、Helix 解码与 I2S 输出，可评估复用；切换上游 URL 后要重新验证 TLS、重定向、范围/分块响应与设备堆内存。
- 硬件为 ESP32-C3，无 PSRAM。任何 S3/PSRAM 参考实现都只能作为协议参考，不能直接视为可移植实现。
- `netease-official-firmware/` 属于官方开放平台路线的历史实验，匿名登录仍因公共参数/签名校验失败；不在本计划内继续扩展其业务实现。

## 用户流程与首版范围

1. 首次启动配置 Wi-Fi；后续连接已保存的网络。
2. 设备通过 HTTPS 获取二维码内容并显示；用户使用网易云音乐客户端扫码授权。
3. 设备轮询扫码结果，成功后将登录 Cookie 等必要状态保存到设备 NVS。
4. 设备直接获取用户歌单、分页读取歌曲并显示。
5. 设备直接获取所选歌曲的可播放 MP3 URL，连接 CDN 并流式解码播放。
6. 重启后复用有效登录态；过期或失效时明确返回扫码登录，不伪造已登录状态。

首版只覆盖扫码登录、登录态持久化、歌单浏览、歌曲列表、播放/暂停/停止与现有音量控制。暂不加入搜索、推荐、收藏修改、歌词、离线缓存、多账号或中转回退。需要登录验证码、风控挑战或额外人工验证时应明确提示，不尝试规避。

## 协议实现选择与许可证

已找到候选参考项目 `https://github.com/han0519/desktop-robot-companion`，其中 `main/ne_client.c` 和 `main/ne_client.h` 包含适用于 ESP-IDF 的网易云请求、扫码登录、Cookie、歌单与播放地址相关实现。该项目作者报告的目标硬件为 ESP32-S3；代码使用 PSRAM 分配，不等于已支持本项目 C3。

开始移植前必须在本机取得仓库快照，审查其许可证、上游依赖、代码来源和当前接口实现。若没有明确授予所需复制、修改和分发权利的许可证，不复制其实现代码；改为依据协议行为独立实现，或选择许可证兼容的实现。协议逆向接口可能变化，不能将单一上游项目的 README 声明当作稳定性或真机验收证据。

协议采用原则：复用有许可证的实现时保持其许可与版权声明；将传输、加解密、认证流程、业务解析拆成小接口；避免把第三方协议实现整个带入固件；以可审阅的官方客户端交互和项目自身测试固化请求/响应行为。不得记录或打印用户 Cookie、二维码密钥、账号令牌、密码或完整敏感响应。

## 架构与范围边界

- 固件入口和 Wi-Fi 配网页保留现有工程的已验证部分。扫码页直接呈现协议返回的二维码，不要求填写 Relay URL、注册码或服务器地址。
- 建立设备端 `netease_direct_client`（名称可按现有构建结构调整），负责 HTTPS、请求加密/签名、响应解密、超时、JSON 有界解析和错误映射。
- 认证模块负责二维码申请、状态轮询、用户会话持久化、会话有效性检查及明确的重新登录状态。Cookie/会话密钥使用独立 NVS 命名空间；不得复用官方实验版 Token 格式或中转版设备注册状态。
- 播放器只接收已验证、未过期的音频 URL；复用音频解码组件前，确认重定向行为、证书验证、URL 长度、分块传输与 CDN TLS 所需堆内存。
- 所有网络和加解密操作运行于后台任务，LVGL 访问遵守锁约定。响应采用可控上限及分页，禁止假设 C3 有 PSRAM。
- 新实现先在现有固件目录内使用独立组件和独立认证命名空间验证，以避免再复制一份庞大固件树；发布切换需等端到端真机验收后再决定。中转服务源代码继续保留，不增加自动中转降级。

## 实施阶段与验收

### 阶段 0：来源、许可证与环境核查

- 将协议候选上游与模拟器分别放入仓库外的专用目录，检查提交版本、许可证、构建说明、运行依赖、PSRAM 假设及模拟器自动化接口。
- 记录候选协议实现的许可证结论；如果许可证不允许目标分发方式，停止复制并改选独立实现来源。
- 确认可使用的 ESP-IDF 5.5.4 构建环境、开发板连接方式及模拟器屏幕输入输出方式。模拟器本身不能替代 C3 实际内存、TLS 和音频硬件验证。

### 阶段 1：固件与模拟器可复现基线

- 在修改前记录现有固件构建结果、启动与界面截图/日志、模拟器运行方式。
- 建立模拟器驱动和设备输入/画面捕获流程；用现有固件完成一次可重复的启动、按键导航与配网页检查。
- 明确区分模拟器验证（UI、状态机、请求调度）与真机验证（C3 堆内存、签名、TLS、音频输出和真实登录）。

### 阶段 2：协议客户端主机验证

- 在不带真实账号数据的主机测试中验证请求编解码、二维码状态、歌单分页、曲目解析、播放地址解析、异常响应、超长输入和超时。
- 用专用脱敏响应样例测试登录流程状态机；没有协议依据的字段不猜测，不用 mock 成功结果通过真机流程。
- 将加解密及纯逻辑与 ESP-IDF/界面分离，覆盖主要失败分支。

### 阶段 3：设备扫码登录与会话存储

- 设备显示真实二维码并完成真实客户端扫码授权。
- 确认登录态只在设备本地保存；断电重启后复用；清除会话能回到扫码流程。
- 验证未扫码、用户拒绝、二维码过期、网络中断、接口返回错误、会话过期均有可见且可重试的结果。
- 在测试日志与崩溃信息中确认没有泄露 Cookie、授权码或二维码密钥。

### 阶段 4：C3 资源及音频直连

- ESP-IDF 构建通过，并报告各关键阶段的最大可用内部 RAM/堆、最低空闲堆和任务栈余量。
- 真机完成歌单读取、分页歌曲列表和一首有播放权限的 MP3 播放；音频 HTTP 直接连接 CDN，抓包/日志确认数据不经过本仓库服务。
- 测试 CDN HTTPS 证书、跳转域名、超时、断网恢复、播放结束、暂停/恢复与反复切歌；记录设备限制，不将仿真成功写成硬件成功。

### 阶段 5：发布验收

- 构建和现有仓库必需检查通过；默认中转版文件没有意外变化。
- 至少完成真机扫码、重启免登录、歌单浏览和可播放歌曲播放。
- 开源许可证及第三方声明随发布包保持完整；配置样例不含真实 Cookie、密钥或个人数据。
- README 明确直连方案的外网需求、协议兼容风险、登录失效行为与已验证设备范围。

## 当前外部依赖与风险

- 网易云非官方接口的路径、加密协议、二维码授权和 CDN URL 可能变化；依赖接口变化时需更新实现并重新验证。
- 部分歌曲受会员、版权区域、试听时长或账号权限限制。播放地址为空或受限必须作为错误显示。
- C3 无 PSRAM；登录、JSON 解码、证书链和 MP3 播放并发的内存峰值是主要实现风险。
- `passportsim` 可用于 FoloToy UI/按键自动化，但模拟器不等价于真实 ESP32-C3、网络设备或音频外设。
- 直连意味着设备与网易云/CDN 通信；用户账号会话只存于设备。清晰解释首次授权和本地登出/擦除行为。

## 协议来源与实现约束

- 参考 `han0519/desktop-robot-companion` 快照位于 `/home/phoenix/code/han0519-desktop-robot-companion-bf2b1b2/`，仓库带 MIT 许可证，版权行仍为占位内容。仅检查协议，没有整份移植 S3/PSRAM 客户端。
- 协议行为交叉核对 [api-enhanced 固定版本](https://github.com/neteasecloudmusicapienhanced/api-enhanced/tree/984cc021b8598cf94c22134f32a8426887fb2de7) 的 `util/request.js` 和二维码、账号、歌单、歌曲详情、播放 URL 模块；许可证 MIT，Copyright (c) 2013-2022 Binaryify。组件是针对 C3 独立编写的 C 实现，不引入 Node 运行时或上游服务。
- API 固定网易云 HTTPS 域名并校验证书；API 不跟随跳转，音频不携带 Cookie。会话位于 `netease_session` NVS，Wi-Fi 位于 `netease_wifi`。客户端由单 worker 串行调用，不支持并发或多账号。
- 首版最多保留前 20 个歌单，更多时计数显示 `+`；每页最多 15 首歌曲，翻页重新流式读取 trackIds，再批量读取该页歌曲。流式响应上限 4 MB、深度 24 层；普通响应上限 16 KB，WEAPI JSON 上限 1200 字节，包含会话 header 的 EAPI JSON 上限为 Cookie 上限加 1024 字节，同时受 8192 字节编码请求体上限约束。超限明确失败，不伪造空列表。
- 仅支持 MP3，不播放 `freeTrialInfo` 标识的受限试听，不绕过会员、地区、版权或风控。Cookie 刷新先在 RAM 生效，账号验证成功时持久化；断电后的实际刷新行为需要真机验收。
