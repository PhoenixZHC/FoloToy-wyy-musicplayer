# Folo Music 2.1.1

Local build dated 2026-11-03, Asia/Shanghai. Target: FoloToy AI Passport, ESP32-C3, 8 MiB flash, no PSRAM. No Git tag or public release was created.

## Changes

- Disable modem sleep in the playback Wi-Fi driver and check configuration errors.
- Separate downloading from decoding through a bounded 16 KiB queue; prebuffer 8 KiB on startup and after starvation, with a visible buffering state.
- Add bounded Wi-Fi reconnect and validated HTTP Range/If-Range recovery. Incomplete responses fail explicitly instead of advancing the track.
- Suspend speculative metadata prefetch during audio activity. Release idle API TLS before playback and after explicit browsing to reclaim RAM.
- Retain the display, clock and automatic screen-off features from 2.1.

## Verification and limits

ESP-IDF 5.5.4 direct build, merged-segment verification, strict 8 MiB packaging and four packaging regressions passed. Before source delivery, the complete static gate passed: all 14 host executables, four packaging regressions, repository checks and workflow lint. Pinned actionlint 1.7.12 was downloaded through the official GitHub API and its SHA-256 verified. This supersedes the earlier missing-actionlint limitation; the earlier three client reruns remain historical evidence.

The same repaired playback code, still labeled 2.1, was flashed and tested: one track played normally for about 3 min 32 sec and advanced automatically; the second continued for about 110 sec. All 61 captured timing reports showed cumulative underruns=0, with no playback failure or crash markers. The first track's free heap after audio initialization increased from 4,340 to 31,492 bytes after releasing idle API TLS. Byte comparison confirmed that differences from the tested binary are confined to the app descriptor and final integrity bytes. This 2.1.1 package only updates the version metadata and has not been flashed again; the installed device still reports 2.1.

Deliberate hotspot disconnection/Range recovery, concurrent browsing, prolonged outdoor weak networks, power and listening quality remain unaccepted. Do not infer those results from a normal playback test. Details and historical evidence: [hotspot development record](../../firmware/ai-passport/docs/development/hotspot-playback.md).
