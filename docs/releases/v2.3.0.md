# Folo Music 2.3.0

Date: 2026-11-11 (Asia/Shanghai). Source: Ubuntu development computer. Stable version for local firmware delivery and source push.

## Changes

- Single-page network connectivity test under Settings, with background DNS/HTTPS checks, cancellation and explicit busy/memory states. Any valid HTTP response, including 404, establishes reachability; details stay in logs.
- Real QQ album artwork and timed LRC through the shared provider. Artwork is sampled to 60×60; bounded lyrics and explicit media failure states preserve playback.
- Expand only 9, 12 and 24 px metadata fonts to 12,601 characters each, including Japanese kanji/kana and 2,350 common Korean syllables. Share 12 px between artists and lyrics; keep 24 px playback titles.
- Dedicated top-right battery percentage. Apply the default 80-byte 4.2 V Li-Poly profile and bounded CW2017 readiness polling, addressing unavailable SOC 0xFE. The profile has not been calibrated for this cell over a full charge/discharge cycle.
- Save 12 KiB of audio queue/input RAM and defer decoder allocation until initial prebuffering, addressing TLS allocation failures after adding media.

## Validation and remaining limits

- Build: ESP-IDF 5.5.4 direct build, embedded 2.3.0, merged segments, exact 8 MiB, blank regions, read-back and hashes passed.
- Host: 25 C executables, 14 Python regressions (5 packaging, 9 login-tool), 4 font tests and repository/workflow checks passed. Japanese/Korean and Chinese lyric day/night previews passed.
- Device: app-only development firmware labeled 2.2.0 passed independent verification, QQ networking/session restoration/browsing and actual MP3 decoding. The user accepted audio, artwork, synchronized lyrics, single-page network results, Japanese/Korean text, matching artist/lyric sizes and battery percentage. Gauge logs reported 98% at 4145 mV. See [validation evidence](../network-qq-media-validation.md).
- Unverified: this 2.3.0 version-label build has not been flashed again. Long/weak-network playback, all media failure paths, full NetEase/platform-switch/logout regressions, non-empty QQ favorites and battery calibration remain open. One brief underrun recovered during the multilingual build test; zero-stutter operation is not claimed.
- Two prior defects remain: pause during buffering may update only the UI, and queue state commits before asynchronous startup succeeds without rollback on failure. See the [review](../code-review-2026-11-10.md).

MIT, upstream and font licenses remain. Service permissions, membership restrictions and unofficial API changes still apply.
