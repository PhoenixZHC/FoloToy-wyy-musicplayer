# Folo Music 2.2.0

Date: 2026-11-10 (Asia/Shanghai). Source device: Ubuntu development computer.

## Changes

- Add NetEase / QQ Music selection after networking, separate platform sessions, shared settings and current-platform logout.
- Independently implement QQ Music HTTPS requests, MQTT-over-WebSocket QR login, bounded JSON parsing, playlist paging and authorized full MP3 playback. No relay server is required; QQ artwork and lyrics are not implemented.
- Add persistent sequential/shuffle modes, playlist-wide ordering, previous-track history and platform/account/playlist/revision isolation. Playback mode is the first long-OK navigation item.
- Release browsing caches before playback, allocate page workspaces on demand, compact QQ playlist identifiers and stop the old stream before fetching the next page.
- Correct shared platform text and track-loading messages. Add an explicit expected-version option to the packaging CLI.

## Validation and remaining limits

- ESP-IDF 5.5.4 product direct build, merged-image verification, embedded 2.2.0 version, exact-8-MiB packaging, read-back and checksums passed.
- Static validation: 21 C host executables and 14 Python tests passed (9 login-tool and 5 packaging tests), plus repository/workflow checks.
- Device delivery: app-only programming and independent verify_flash passed; 0x0–0xffff matched the private preflash backup, preserving the bootloader, partition table and NVS/PHY. Boot reported 2.2.0. The first attempt could not find the saved network; after the user enabled the original hotspot, the device acquired an IP, synchronized time and reached platform selection. Login and complete playback were not rerun. Details are in [current status](../CONTEXT.md).
- Prior QQ preflight passed a full MP3, pause/resume and restart session restoration. The dual-platform development build also passed basic QQ browsing and random cross-page track changes. Those dated results do not constitute a complete 2.2.0 playback rerun.
- Known defects remain: pause during buffering can update only the UI; ordering commits before asynchronous audio startup succeeds and is not rolled back on startup failure. See the [code review](../code-review-2026-11-10.md).
- Long playback/TLS stability, full shuffle rounds/previous history, NetEase and platform-switch/logout regressions, non-empty QQ favorites and weak-network behavior are not fully accepted. Service permissions and VIP restrictions still apply. QQ artwork/lyrics are unavailable.

MIT licensing and upstream/font licenses are retained; protocol code is independently implemented.
