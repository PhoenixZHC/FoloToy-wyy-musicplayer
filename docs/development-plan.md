# Folo Music 后续开发计划

更新时间：2026-11-11T10:45:00+08:00（Asia/Shanghai）；来源设备：Ubuntu 开发电脑。

状态：两项功能均已实施，正常使用路径已由用户实机确认，正式归入 2.3.0。后续新增日韩字库、统一歌手/歌词字号及电量百分比也经用户确认。下列清单为原始要求，未逐条实机覆盖的组合/异常验收保持未勾选；不得将正常使用验收扩张为全部故障场景通过。见[2.3.0 说明](releases/v2.3.0.zh_CN.md)及[实施验证记录](network-qq-media-validation.md)。

## 一、设置内网络连通测试

目标：用户能够在设备上主动测试网络连通性，并区分 Wi-Fi 未连接、未取得 IP、域名解析失败和平台安全连接失败，不能仅凭取得 IP 就报告网络正常。

### 范围与交互

- [x] 在「设置 → 网络」增加「网络连通测试」，保留「重新配网」与「返回设置」。
- [x] 按后续用户要求只显示单页连通结论；Wi-Fi/IP/时间/DNS/HTTPS 分项保留日志。
- [ ] 对当前所选音乐平台的实际服务域名测试 DNS 解析及 HTTPS 连通性；网易云和 QQ 分别验证。不要求已登录，不调用退出、刷新凭据等会改变账号状态的操作。
- [x] 按用户 2026-11-11 要求精简为一页，只显示检测中、网络连通或网络未连通，失败保留一句原因，不显示 IP/DNS/HTTPS 分项或 HTTP 状态码。任何有效 HTTP 响应均表示平台服务可达。
- [ ] 提供 OK 重试、长按 OK 返回；播放占用或检测资源不足显示检测未完成，避免误判网络不通。检测范围为当前平台服务连接，不验证登录、歌曲权限或音频 CDN。
- [ ] 检测在后台执行；为 DNS、连接、读取及整轮检测设置有界等待，返回后旧结果不得更新已退出页面。不得阻塞按键或 LVGL。
- [ ] 第一版播放期间只展示基础状态；主动完整检测时提示暂停播放后执行，不擅自停止音乐。暂停后的 TLS/音频资源仍需核验，内存不足必须明确提示，不能继续冒险分配。
- [ ] 不修改 Wi-Fi、账号、播放队列或持久化设置，不关闭证书校验，不新增中转或常驻轮询。

### 实施入口

现有 `firmware/ai-passport/main/netease_app.c` 负责网络菜单、Wi-Fi 事件及 worker，`netease_app_logic.c/.h` 负责页面与按键状态机，`device_music_ui.c/.h` 负责展示。增加独立的有界检测逻辑，复用现有平台选择和证书配置；避免复用会改变登录态的业务请求。超时、结果分类及取消规则应可独立主机测试。

### 验收

- [ ] 正常网络下，两平台均能完成各检测项；记录实际耗时，不预先承诺秒数。
- [ ] 覆盖 Wi-Fi 断开、未取得 IP、热点无互联网、DNS 失败、时间无效、TLS 失败、连接/读取超时及 HTTP 错误响应；结果分类与实际故障一致。
- [ ] 检测中返回、重复重试及切换平台不串结果；退出后无旧页面访问、资源泄漏或账号设置变化。
- [ ] 播放期间提示符合上述约定；暂停后检测及恢复播放稳定，记录内部空闲堆、最大连续块和栈余量。

## 二、QQ 音乐封面与歌词

目标：QQ 音乐播放页显示当前歌曲的真实封面及随播放时间同步的歌词，复用现有网易云媒体展示能力，继续由设备直连 QQ 音乐及其 CDN。

### 范围与实现

- [x] 根据真实 QQ 响应核实歌曲、专辑标识与封面地址，以及歌词接口、鉴权、编码和歌词格式；按当前 MIT 路线独立实现协议，不复制 GPL 参考代码。测试数据脱敏，不保存账号凭据。
- [x] QQ 直连组件提供封面信息和歌词读取能力，经 `music_provider.c/.h` 按平台分发；不得把 QQ MID 强转为网易云数字 ID。
- [x] 在 `netease_app.c` 当前显式跳过 QQ 封面/歌词的位置接入；复用 `music_artwork.c/.h` 的有界下载/解码，以及 `music_lyrics.c/.h` 的时间行匹配和现有播放页，不另做一套播放器。
- [ ] 封面只缓存当前歌曲一张，限制下载字节、图片尺寸和解码内存；验证 URL、重定向及实际缩图能力。无封面、下载失败、格式不支持、超限或内存不足显示明确状态，不保留上一首封面冒充当前歌曲。
- [x] 第一版实现按时间行同步的歌词，不增加逐字高亮、翻译或罗马音。处理 UTF-8、多时间戳、暂停/继续和切歌；无歌词、纯音乐、无时间戳歌词、读取失败及超限分别显示可理解状态。
- [ ] 封面与歌词均在后台有界加载，加载失败不阻止可用音频播放，并给出可见反馈；媒体加载后释放闲置连接及临时内存，再启动音频。具体内存上限按 C3 实测确定，不依赖 Flash 余量推断 RAM 足够。
- [ ] 结果绑定当前平台、账号和歌曲；单一 worker 串行化媒体请求，退出应用、返回平台或退出账号时丢弃旧结果，先解除 UI 引用再释放图片和歌词。普通导航仍允许当前播放在后台继续加载，完成时不抢回已离开的页面；网络检测额外使用请求代次隔离取消后的快照。

### 验收

- [ ] 实机确认真实 QQ 歌曲封面和歌词与当前曲目一致；覆盖有歌词、无歌词、纯音乐及封面缺失。
- [ ] 歌词随播放推进切换，暂停不前进，继续后同步；覆盖多时间戳、长歌词、非法响应和非时间轴歌词，不把静态歌词误当同步歌词。
- [ ] 封面/歌词超时、无权限、解码失败、超限或内存不足时提示准确，音频仍可播放，无崩溃和静默错误。
- [ ] 连续手动/自动切歌、跨页、顺序/随机、切换平台及退出账号不串封面或歌词，无累计资源泄漏；回归网易云现有封面、歌词和播放。
- [ ] 记录封面下载/解码、歌词读取、启动播放及连续切歌阶段的内部空闲堆、最大连续块与栈余量，用实测确认资源上限和播放稳定性。

## 实施顺序与交付要求

先完成网络连通测试，再实现 QQ 封面与歌词；两项独立验收。现有缓冲态暂停遗漏、异步播放成功前提交队列问题仍单独保留，不因新增需求而视为已解决；若阻塞本计划验收，明确记录依赖。

每项实施后运行相关协议、解析、状态机和资源生命周期主机测试，以及项目要求的静态门禁、固件构建及镜像验证。已完成的本轮证据见[实施验证记录](network-qq-media-validation.md)。实机验证与主机验证分开报告，未完成的检查明确保留。更新相关说明和当前状态；提交、推送、分区调整及烧录按用户授权执行，不由本计划自动授权。
